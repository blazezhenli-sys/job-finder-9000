# Hiring Signal Discovery

Self-hosted, deterministic hiring-signal monitoring for Bluesky, Hacker News, Mastodon, and Reddit, with a separate ATS listings stream for Greenhouse, Ashby, and Lever. It runs a Fastify dashboard and durable background worker against PostgreSQL. No browser session is needed for ingestion.

## Quick start

1. Copy `.env.example` to `.env`, change `DASHBOARD_PASSWORD`, and set `APP_PORT` if port 3000 is already in use.
2. Run `docker compose up -d --build`.
3. Open `http://your-server:3000` and sign in with the configured basic-auth credentials.

Coolify can deploy this repository as a Docker Compose project. Set `APP_PORT` to the host port you want to publish; the application remains on internal container port 3000. Keep the Postgres volume persistent. Set the same environment variables in Coolify; SMTP values stay server-side and are never returned by the API.

For local development, run PostgreSQL, set `DATABASE_URL`, then use `npm install && npm run dev`. Set `DEV_MODE=true` to enable the “Load sample posts” action in the dashboard. The app runs migrations automatically at startup.

## Architecture and limitations

- `src/sources` contains source adapters. The Posts stream is currently disabled by default with `ENABLE_POSTS=false` but remains available as a work in progress: Bluesky uses the public Jetstream WebSocket and resumes with its last event cursor; Hacker News polls the public API; Mastodon consumes configurable public-instance authenticated WebSocket streams; Reddit uses an OAuth application token and polls selected subreddit posts/comments.
- `src/pipeline.ts` normalizes text, applies editable phrase/regex rules, extracts explicitly mentioned technologies and employment terms, and deterministically classifies each match as direct hiring, software request, employee referral, firsthand announcement, aggregated listing, or uncertain. Signal quality is kept separate from personal relevance; there is no LLM classification.
- Every persisted post retains its original source URL, contact methods, classification reasons, and an author profile. Aggregated posts remain available through the category filter and are excluded from notifications when suppressed. Author classifications and an exact account/domain/text aggregator registry are editable in the dashboard.
- Location requirements are extracted conservatively from explicit wording: work mode, named places, allowed/restricted scope, time zones, and the source evidence used. Ambiguous posts remain `unknown` rather than being guessed.
- A location-fit layer evaluates those signals against the saved base location and timezone, producing excellent/good/possible/poor/unknown results. The feed can sort/filter by fit and minimum score, and notification eligibility includes the configurable minimum fit score.
- The Listings tab is an independent pipeline. It automatically polls Remotive’s public remote-jobs API, and can optionally poll Adzuna when `ADZUNA_APP_ID` and `ADZUNA_APP_KEY` are configured. You can still add public Greenhouse, Ashby, or Lever boards by provider and identifier/URL. The first successful poll establishes a baseline, and later new postings can enter a separate email notification queue. Each listing retains the source page and direct application URL, plus the original employer, department, location, work mode, employment type, seniority, compensation, freshness, and saved/applied/dismissed state. The Listings view can filter by employer, department, employment type, seniority, location/region, salary currency and minimum salary, provider, status, work mode, and location fit.
- Company Profiles build on the existing `employers` registry rather than creating a duplicate company table. The Companies view summarizes active listings, conservatively classified engineering specialties and technologies, recent post-initial observations, remote/contract counts, ATS boards, and active openings. Successful board polls now record company activity history without treating an initial snapshot as historical hiring. Profiles also expose evidence-backed hiring signals, a bounded prospect score with contributing factors, and lightweight private prospect status/notes. Company metadata fields are available for later verified enrichment and manual correction; ATS slugs are not treated as authoritative company identity.
- ATS board discovery is a separate resumable job. It harvests Greenhouse, Ashby, and Lever URLs from Internet Archive CDX, falls back to Common Crawl, supplements recent runs with urlscan, extracts/deduplicates board identifiers, validates candidates with lightweight `HEAD` requests, and imports only validated boards. Archive responses are streamed rather than buffered as one complete payload; the cursor records the current provider/domain, archive rows, candidate count, and last URL for live monitoring. URLs found in existing or newly ingested Posts are also recorded, including aggregator-classified posts. Discovery stores source, attempts, status, progress, and retry timestamps in PostgreSQL; it never imports historical jobs or creates notifications.
- `src/worker.ts` is the always-on worker loop. The default Docker command starts it with the web server in one process; `start:web` and `start:worker` are also available for separate Coolify services.
- PostgreSQL provides idempotency, notification retry state, source health counters, and restart recovery. Irrelevant matched-free posts are not stored; a configurable retention task removes old opportunities.
- Bluesky Jetstream is high-volume, so only posts matching a positive rule are persisted. On a first run, it starts at the current stream position; set `NOTIFY_RECOVERED=true` if recovered posts should notify. Mastodon and Reddit are disabled by default; enable them with `ENABLE_MASTODON=true` or `ENABLE_REDDIT=true`. Reddit requires `REDDIT_CLIENT_ID`, `REDDIT_CLIENT_SECRET`, a descriptive `REDDIT_USER_AGENT`, and a comma-separated `REDDIT_SUBREDDITS` allowlist. Mastodon accepts `MASTODON_ENDPOINTS` as a JSON array of hostnames plus `MASTODON_TOKENS_JSON` mapping each hostname to its own user token with `read:statuses`. Legacy `MASTODON_INSTANCES` and `MASTODON_ACCESS_TOKEN` remain supported for one endpoint. Historical opportunities are reclassified on worker startup without creating old notifications.
- Listings are enabled by default and poll every hour; configure `ENABLE_LISTINGS`, `LISTINGS_POLL_INTERVAL_MS`, and the bounded `LISTINGS_POLL_CONCURRENCY` worker count as needed. A board’s initial snapshot does not generate notifications, preventing a newly added board from flooding the inbox. Remotive is polled every six hours by default because its public feed is delayed and intended for low-frequency access; configure `REMOTIVE_POLL_INTERVAL_SECONDS` if needed. Adzuna supports configurable countries, query, location, and poll interval through the `ADZUNA_*` variables.
- Discovery is enabled by default and runs an initial full job, then recent jobs daily. Configure `ENABLE_LISTING_DISCOVERY`, `LISTING_DISCOVERY_INTERVAL_MS`, and the bounded `LISTING_DISCOVERY_VALIDATION_CONCURRENCY` worker count; trigger a manual full or recent run with `POST /api/listing-discovery/jobs` and inspect progress with `GET /api/listing-discovery/jobs`. Validation requests still use a shared 250ms start-rate limit, retries, and resumable candidate state. The reference implementation’s large generated board cache was not imported because it has no per-record provenance/freshness metadata; discovery generates our own local, auditable registry instead.
- The Market section is a separate observability surface over Listings. It uses server-side filters, full-text search, facets, pagination, sorting, country/region and remote-eligibility fields, salary/publication windows, and source links. Listing classifications are deterministic and versioned; technologies are explicit mentions from a database-backed alias taxonomy, not proof of production usage or a confirmed requirement. `GET /api/market/taxonomy/technologies` and `PATCH /api/market/taxonomy/technologies` expose taxonomy maintenance.
- Temporal analytics are deliberately conservative. The first successful board poll is a baseline; it creates no historical “new listing” activity or notification. Later successful polls record append-only listing events, while missing listings require three consecutive successful observations before removal. Daily snapshots are idempotent and expose both the full observed index and a `stable_28d` cohort (at least 25 successful observation days in the preceding 28-day window). Stable-cohort changes are observed posting changes, not confirmed hires, and coverage fields remain attached to trends and signals.
- Company daily snapshots retain active/new/removed/remote/contract counts plus specialty, technology, employment-type, and work-mode composition maps. The worker persists deterministic company and market signals only after minimum monitoring history; signals include supporting listing IDs, explanations, comparison windows, sample sizes, and data-quality notes. Signal evidence can be opened from the Market view and is always linked back to the original listing source.

## Tests

`npm test` covers normalization, rule detection, scoring, deduplication semantics, timestamp handling, and notification eligibility. `npm run build` verifies the production TypeScript build.
